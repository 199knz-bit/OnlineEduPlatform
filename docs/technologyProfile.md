# Технологичен профил на OnlineEduPlatform

## Описание на системата
Онлайн платформа за обучение, която позволява управление на курсове, учители и записване на студенти. Системата е предназначена за малки учебни центрове и преподаватели, които искат да организират курсовете си и да следят записаните студенти. 

Системата се състои от **две взаимодействащи части**:
1. **Уеб приложение (ASP.NET Core MVC)** – обработва заявки, показва изгледи и съдържа бизнес логиката.
2. **База данни (SQLite)** – съхранява данните за курсове, учители и студенти.

Взаимодействието между тях се осъществява чрез **Entity Framework Core**, който превежда C# обектите в SQL заявки и обратно.

---

## Слой 1: Потребителски интерфейс
**Избор:** ASP.NET Core MVC (Razor Views) + Bootstrap 5

**Обосновка:**
- **Зрялост:** ASP.NET Core MVC е установена технология с дългогодишна история и стабилна екосистема.
- **Наличие на кадри:** Екипът (аз) владее C# и Razor синтаксис, което намалява времето за разработка.
- **Живост на общността:** Официалната документация на Microsoft е винаги актуална.

**Отхвърлени алтернативи:**
- **React SPA** – *Причина:* Изисква отделен Node.js сървър и усложнява Docker + Razor Views е вграден част на ASP.NET.

**Време за смяна:** часове

## Слой 2: Интеграция и API
**Избор:** Вътрешни извиквания на методи (Controller → DbContext) без REST API.

**Обосновка:**
- **Оперативна съвместимост:** Всичко е в един процес, няма мрежова комуникация, което намалява латентността.
- **Наблюдаемост:** Грешките се виждат директно в логовете на ASP.NET Core.
- **Време за смяна:** Интеграцията може да се промени сравнително лесно и бързо при нужда.

**Отхвърлени алтернативи:**
- **REST API + отделен frontend** – *Причина:* Добавя мрежова латентност.

**Време за смяна:** дни

## Слой 4: Контейнер и оркестрация
**Избор:** Docker (един контейнер)

**Обосновка:**
- **Зрялост:** Docker е установена технология от 2013 г. с широка производствена употреба. Стабилните версии са предвидими и добре документирани.
- **Живост на общността:** Огромна общност, хиляди готови образи, активна поддръжка. При проблем лесно се намира решение.
- **Оперативна съвместимост:** Docker работи с всички съвременни ОС и се интегрира с GitHub Actions.
- **Наблюдаемост:** Docker предоставя вградени логове (`docker logs`) и метрики (`docker stats`), което улеснява диагностиката.

**Отхвърлени алтернативи:**
- **Kubernetes** – *Причина:* Прекалено тежък за една услуга.

**Време за смяна:** седмици

## Слой 7: Хранилище на данни
**Избор:** SQLite (чрез Entity Framework Core)

**Обосновка:**
- **Зрялост:** Вградена в .NET, нулева конфигурация.
- **Съответствие с качеството:** Поддържа ACID транзакции.
- **Време за смяна:** Ниско – може да се смени с PostgreSQL без промяна в кода (благодарение на EF Core).

**Отхвърлени алтернативи:**
1. **PostgreSQL** – *Причина:* Изисква втори Docker контейнер и мрежова връзка; излишно за текущата задача.

**Време за смяна:** месеци / седмици при смяна от SQLite на PostgreSQL

## Граница на валидност
Този профил е валиден за система с един сървър и до 1 000 курса. При по-голям мащаб трябва да се премине към разпределена архитектура (микросервизи, отделна база данни).

---

## Какво бих променил при 100× натоварване (самостоятелен вариант)

- **Хранилище:** SQLite не поддържа едновременни записи от много процеси. Бих сменил с PostgreSQL, който поддържа конкурентни връзки и репликация. Промяната е лесна, защото EF Core абстрахира базата – сменям само `UseSqlite` с `UseNpgsql`.
- **Кеширане:** Бих добавил Redis за често четени данни (списък с курсове), за да намаля натоварването на базата.
- **Мониторинг:** Бих добавил Prometheus + Grafana за наблюдение на натоварването и грешките.
